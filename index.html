Declarative memory · Temporal Context Model

Forgetting is not always loss

You know the feeling: a name won't come, until someone says its first letter and suddenly it is there. The memory was never gone. Psychologists call this retrieval cue failure: the memory is still stored, but nothing in your current situation leads to it.

Chapters

    1 · Introduction

    This interactive model will focus on memory retrieval and where this memory retrieval can fail, so how a memory can become temporarily inaccessible without being lost. First a baseline for memory formation is needed. Memories are formed in three distinct steps, these being encoding, storage/consolidation and retrieval.

    When you come across a piece of information that needs to be remembered the brain takes in all the context of the situation. Say that you meet a person in the hallway, in order to form a memory the brain records the voice, appearance, emotion, time and place for example. The pattern of neural activity representing this context is stored alongside the memory.

    In order to produce retrieval, your brain needs to recreate the pattern of neural activity associated with a memory. Retrieval failure is the case where this pattern cannot be recreated. This might be because over time your neural activity changes (context drift), and you lack a strong enough cue to return back to a similar pattern of activity. This is what the Temporal Context Model (TCM) illustrates.

    2 · The big idea

    Stored is not the same as reachable

    As mentioned this model focuses on retrieval failure, which can be shown using the widget on the right. This widget is very fundamentally what this whole model shows. It learns a list of words, which is shown in the grey bar. All of these words are stored with the context of when they were learned. The purple bar represents how many of these memories can be retrieved without any cues. The way this happens is a comparison between the current context after multiple events and the context of each word. If the current context and the stored context are similar enough the memory can be recalled. The green bar represents the case in which we give a little hint like the first letter of someone's name for example. Lastly, the box called real forgetting will turn on decay which will affect the strength of the memory this leads to it being harder to recall in general.

    The real forgetting tickable box is represented in the sandbox mode using “True trace decay / event”

    The point of this little widget is to showcase that letting events pass will result in the context drifting which affects how effective recall is.

    3 · Context

    A context is a pattern, and overlap says how alike two patterns are

    So all items are stored with their context, but how is this context stored? It is simply a vector/list of 80 numbers which can range from -1 to 1. In our model it will be showcased using this line of boxes with the orange boxes being negative and the purple boxes being positive values.

    This context consists of all types of information like your location, the time and your emotion for example. It is important to note that one value does not correspond to one aspect of the context. Instead it is a pattern that forms this information.

    So we cannot extract very specific information from these values, but what is most important is the overlap between the two contexts. This is calculated using the dot product between the current context and the item context. The dot product can theoretically range from -1 to 1. However, with an 80-dimensional vector the odds of two random vectors having a dot product below even -0.05 are small, so completely unrelated vectors will usually have an overlap of approximately 0.

    The widget can alter pattern B depending on how strong the overlap is which can be changed with the slider. From this you can see that the pattern becomes the exact same for 1 or totally different for 0.

    4 · Drift

    Every event pushes the context a little further away

    Life does not pause. Each new event brings something new into your head, and the context shifts to make room. In the model, the new context keeps a share of the old one and mixes in the new input:

    tnew = ρ · told + β · tinput

    t stands for the context vector, with tnew being the updated context vector, told being the old context vector and tinput representing the new context that will be added. β is how strongly the new event pushes. ρ is chosen automatically so the context stays a unit length vector, which means a larger β pushes out more of the old context.

    Note that the same formula is also used for Studying and Reinstatement (both explained later), with the difference being that in those situations instead of Drift per event, β stands for Encoding drift and Reinstatement respectively.

    Nothing is erased. The old context is simply diluted, event after event. The bottom strip on the right shows the overlap between the context when a word was studied and the context now. It fades, but at no point is anything deleted.

    In the widget the original context can be seen in the top bar, the context bar below that one is the current context. After letting time pass through clicking the event buttons the context will shift and the overlap will decrease slowly. The slider controls the beta variable so how quickly new context input gets taken up. The higher beta is the more the context drifts. Additionally the second bar lists the current overlap and there is also a bar that shows the overlap per event. With bright purple being high overlap and low saturation being low overlap.

    5 · Studying

    A word is stored together with its context

    Till now we looked at how context is stored and how drift works, but say we study a list of words the same things we saw earlier have an effect on how it is studied. Firstly since drift is updated every event, words learned close together will have more overlap than words studied farther apart.

    Additionally a cue/event, like mentioned in the part “the big idea” can leave its “fingerprints” on the context. Basically meaning that the event will produce a pattern that is similar across all words so the overlap will be bigger.

    To showcase both of these phenomena we can work toward it using the widget here. Firstly on the top we can select which event was present while learning. Words with the same ticked events will have a much higher overlap. Below this we can study the next word or add 3 events or start over. Then we see the context bar for the current word that will be studied when clicking “study next word”. When adding events you can see that the context shifts because the pattern changes. Additionally above the bar it will mention the overlap with the previous word if 1 word was already studied.

    The real important part of this widget is the overlap table, which shows the overlap between the different words. We can see the diagonal that is the overlap between the same word, then close to this diagonal are the words studied recently. What is important to see here is that as long as the words have been studied close to each other the overlap is very high. However, with this widget we can test the effect of drift and also the effect of different events for different words.

    6 · Cues

    A cue works only if it was part of the memory

    To get a word back, the model uses a cue: the current context, plus anything you deliberately bring to mind, such as returning to a place or hearing a song. The cue is compared with the context stored with each word. The more they overlap, the more accessible the word is.

    This is the encoding specificity principle (Tulving and Thomson, 1973): a cue helps only if it was encoded along with the memory. Nothing in the code states it as a rule. It falls out of the arithmetic. If Place A was present at study, its fingerprint is in the stored context, so a Place A cue overlaps with it. Place B was never there, so a Place B cue overlaps with nothing and adds nothing.

    This widget shows the possible selections for present cues during learning and possible cues during recall. Then there are three context bars, the first one shows the context of the 4 words, the second shows the context after 20 events, the last bar shows the context after 20 events with the cue vector added. Then there are two bars which show the probability of recall happening with and without the cue. The orange line on the bars marks a threshold that needs to be passed in order to win the race described next.

    It aims to show clearly how a cue can add to the recall and how a cue that is not there during encoding will not affect recall.

    7 · Retrieval

    Recall is a noisy race between memories

    Till now we only looked at context and cues how they affect overlap, but now we will see how recall is actually simulated. All words in the list have an activation value, which is iteratively nudged upward using a combination of variables. Simply said the overlap and strength of the memory affect the pull value. The activation value rises with this pull value, but also leaks away over time and is held back by competition. Lastly, it is also jostled by noise so recall is still slightly random and not fully deterministic. The first activation value to reach the threshold of 1 will be recalled. If no value reaches the threshold after 120 steps the race will stop and recall has failed.

    What we can actually see in the widget is the option to choose the cue that is present. Then a progress bar for each word with the orange line being the threshold, once it passes the threshold it becomes green and completes fully to represent successful recall.

    Deeper math

    The true formula used is:

    x(t+1) = x(t) + (pull - x(t) - comp) · δt + noise_term

    x is the activation value and it is the variable that is supposed to reach 1. The pull variable is the main driving force towards an activation of 1. It is calculated using gain · strength · overlap. The standard gain is 2.5 and the standard strength is 1. The gain cannot be changed in the sandbox, but the strength can by altering the true trace decay. The second x(t) is the leak factor which scales it so that it slows down at higher activation values. Then there is the comp variable which consists of competition · sum of other activations. This represents the competition between the different memories. Each step is a small slice of time (δt), and in each slice activation changes by only a small fraction of the net push: pull minus leak minus competition. The δt value is 0.05 and lastly there is the noise_term, which is noise · sqrt(δt) · epsilon. Epsilon is a standard normal random number which mostly falls between -2 and 2 and the noise variable has a value of 0.3.

    8 · Reinstatement

    Remembering one word moves you towards its neighbours

    When a word wins, the model does more than output it. The word's stored context is blended back into the current context. For a moment, the mind is partly back in the situation where the word was studied.

    That matters because words studied close together have similar contexts. After a recall, the current context overlaps more with the neighbours of the recalled word. They become more accessible and tend to come out next. This is why one recovered memory can unlock others, and why recalled words come out in clusters that follow the original order.

    This reinstatement variable is very similar to the drift variable since it follows the same formula. So a high reinstatement will mean the input context (the context of the word that was just recalled) has a high effect on the new context.

    In the widget you can recall a word by clicking on it and in the context bar you can see the before and after the recall. You can see how the pattern changes and the overlap value.

    On the bottom the grey bars corresponding to each word show the accessibility which is strength x overlap before reinstatement happened. Then the green bar shows accessibility after reinstatement happened due to the earlier recall.

    This part adds the final aspect of this simulation which is the effect of recall on the current context.

    Using the sandbox

    A loop, not a recipe

    The sandbox is not something to work through once from top to bottom. You build a memory, let time pass, probe it with a test, then change one thing and look again. Almost everything useful you can do with it is some version of that loop.

    Build and wait, together

    Real memories are not stored in one go and then left alone. You learn something, you make time pass, you learn something else. The gaps of time matter, because the context drifts during every one of them, and each word keeps the context it was studied in. The same words studied back to back or spread over a long time make two different memories.

    Test without disturbing

    A test only asks. It does not change what is stored and it does not move the clock. The context it works with is a copy, and that copy changes only when a recalled word pulls its own context back in. So you can test as often as you like: once the list is built, again after more time has passed, again with a different cue. Every test starts from the same moment, which makes the results comparable. The race has noise, so a repeated test can come out differently. Run it more than once before you decide that one result means something.

    Read the result from the top down

    Start with the memories: which words came back, and in what order. Then ask why. The context vectors show how alike the current context, a stored context and the cue are. The race shows what was competing. If a word was recalled, the reinstatement panel shows what that did to the context. The stored associations panel shows what is actually stored.

    Change one thing, then look again

    The model settings describe how the simulation acts, such as how fast context drifts or how noisy recall is. The feature tables describe what the situation contains: which place, song or smell is present when words are studied, while time passes, and at test.

    Change one of these at a time and rerun the same test. With the seed fixed and the same steps in the same order you get the same world, so any difference comes from the thing you changed. Then try a few other seeds to check that the effect is not a quirk of one world. If you lose track of the settings, resetting them to their defaults leaves the memory as it is.
