Declarative memory · Temporal Context Model

Forgetting is not always loss

You know the feeling: a name won’t come, until someone says its first letter and suddenly it is there. The memory was never gone. Psychologists call this retrieval cue failure: the memory is still stored, but nothing in your current situation leads to it.

Skip to the model

1 · The big idea

Stored is not the same as reachable

Every memory raises two separate questions. Is it still stored? And can you get to it right now? The psychologist Endel Tulving called these availability and accessibility. They usually go together, so we rarely notice the difference. But they can come apart, and when they do, you forget something that is still there.

That is retrieval cue failure. The trace is intact, but nothing in your current situation points to it. Give it the right cue and it comes straight back.

On the right, the grey bar is what is stored. The blue bar is what can be reached from where your mind is now. The green bar is what can be reached with the right cue. Tick the box to see real forgetting for comparison: the grey bar itself starts to fall, and no cue can bring back what is gone.

2 · Context

A context is a pattern, and overlap says how alike two patterns are

The model is called the Temporal Context Model. Its central idea is that your mind always has a context: a running snapshot of everything going on at the moment, such as where you are, how you feel and what you were just thinking about. In the model, a context is a list of 80 numbers. Blue cells are positive and orange cells are negative.

No single cell means anything. What matters is the whole pattern, and how much two patterns overlap. Overlap runs from 1 (identical) down to about 0 (unrelated). Two unrelated random patterns still overlap by a little, up to about 0.1 either way. That is the noise floor of the model.

Everything that follows is built on this one measurement.

3 · Drift

Every event pushes the context a little further away

Life does not pause. Each new event brings something new into your head, and the context shifts to make room. In the model, the new context keeps a share of the old one and mixes in the new input:

tnew = ρ · told + β · tinput

β is how strongly the new event pushes. ρ is chosen automatically so the pattern stays the same size, which means a larger β pushes out more of the old context.

Nothing is erased. The old context is simply diluted, event after event. The bottom strip on the right shows the overlap between the context when a word was studied and the context now. It fades, but at no point is anything deleted. As the context drifts it stops pointing at the memories that were stored in it. That is the whole mechanism of forgetting in this model.

4 · Studying

A word is stored together with its context

When you study a word, the model records the context at that moment next to the word. That pairing is the memory trace. It is written once and never changes.

Two things follow. First, words studied one after another get similar contexts, because the context only drifts a little between them. In the grid on the right, neighbouring words overlap strongly and distant words barely do.

Second, anything present while you study, such as a place or a song, leaves its fingerprint in the context of every word studied there. That fingerprint is what a cue can later latch onto.

5 · Cues

A cue works only if it was part of the memory

To get a word back, the model uses a cue: the current context, plus anything you deliberately bring to mind, such as returning to a place or hearing a song. The cue is compared with the context stored with each word. The more they overlap, the more accessible the word is.

This is the encoding specificity principle (Tulving and Thomson, 1973): a cue helps only if it was encoded along with the memory. Nothing in the code states it as a rule. It falls out of the arithmetic. If Place A was present at study, its fingerprint is in the stored context, so a Place A cue overlaps with it. Place B was never there, so a Place B cue overlaps with nothing and adds nothing.

The orange line on the bars marks roughly how much overlap a word needs to win the race described next.

6 · Retrieval

Recall is a noisy race between memories

Overlap sets how hard the cue pulls on each word. Every word has an activation that rises under that pull, leaks away over time, is held back by competition from the other words, and is jostled by noise. The first word to cross the threshold is recalled.

Because of the noise, the same setup can give a different winner each time. But when the pull is far below the threshold, as it is for a cue that does not match, no amount of waiting helps. The memories are stored and the race still never produces a winner. That is retrieval cue failure, produced by the model instead of written into it.

7 · Reinstatement

Remembering one word moves you towards its neighbours

When a word wins, the model does more than output it. The word’s stored context is blended back into the current context. For a moment, the mind is partly back in the situation where the word was studied.

That matters because words studied close together have similar contexts. After a recall, the current context overlaps more with the neighbours of the recalled word. They become more accessible and tend to come out next. This is why one recovered memory can unlock others, and why recalled words come out in clusters that follow the original order.

In the chart, grey bars show accessibility before the recall and green bars show it after. Any word whose green bar passes the orange line is now likely to win.

Using the sandbox

Three steps, then the panels

The sandbox below puts all of this in one place. Controls are on the left and the panels showing what the model is doing are on the right. Work down the three numbered cards:

  1. Build the memory. Study next encodes one word using the highlighted row of the study grid, in whatever context you are in at that moment. Reset & study whole list does the whole list at once.
  2. Let time pass. Each event moves the context. Add one, five or twenty.
  3. Test recall. Start test runs the race. With Pause after each recalled word ticked, it stops as soon as one word wins, so you can read the reinstatement panel. Untick it to let the test run to the end.

Features of the world are things like a place or a song. During wait & test keeps a feature present in every event, like staying in the same room. Use as cue adds it to the retrieval cue. The study grid decides which features are present when each word is studied.

What the sliders do

List length
The most words you can study.
Encoding drift β
How far the context moves each time a word is studied. High values give words more distinct contexts.
Drift per event β
How far the context moves with each event while time passes. This is the main forgetting-speed dial.
Reinstatement β
How strongly a recalled word pulls its context back in. At 0, reinstatement is off.
Feature strength
How strongly ticked features count against a random input when events happen.
Cue weight
How strongly the ticked cue features count against the current context.
Noise
How much randomness the race has. At 0 it is nearly deterministic.
Competition
How strongly active words hold each other back. High values give more winner-takes-all recall.
True trace decay
The share of each trace lost per event. At 0, all forgetting is cue failure.
